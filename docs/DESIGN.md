# Design

Why the tool is built the way it is. The first half lists the decisions taken, numbered and never deleted:
a decision that changed is marked **superseded** and points at the one that replaced it. The second half
lists the reasonable alternatives that were not built, so a choice can be revisited with the reason in front
of you. How the parts fit together is in [ARCHITECTURE.md](ARCHITECTURE.md).

## Decisions

| #   | Decision                                                                                                                                                                                                           | Why                                                                                                                                                                                                                                                              | Status                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| D1  | Browser engine: **Stagehand 3.x on top of Playwright**, sharing one Chromium                                                                                                                                       | Stagehand gives `act` / `observe` / `agent` with self-healing selectors; Playwright gives deterministic replay and the evidence. Same browser, no second launch.                                                                                                 | active                |
| D2  | Language: **TypeScript**                                                                                                                                                                                           | Types for a long-lived tool.                                                                                                                                                                                                                                     | superseded by D3      |
| D3  | Language: **JavaScript (ESM) + JSDoc types**, checked by `tsc --checkJs` in CI                                                                                                                                     | Same type safety in the editor and CI, no build step, faster to iterate on a 5-day deadline.                                                                                                                                                                     | active                |
| D4  | **Agents author and repair; plain Playwright replays.** A passing agent run is saved as JSON steps and replayed with zero LLM calls                                                                                | Cost and flakiness: the second run of a test should be as cheap and repeatable as a hand-written Playwright test.                                                                                                                                                | active                |
| D5  | **The judge never trusts the agent's claim of success.** Pass/fail comes from harness evidence: DOM, URL, console, network, screenshots                                                                            | An LLM agent will say "done" when it is not. Asymmetric trust: the agent's own "I failed" _is_ accepted as evidence.                                                                                                                                             | active                |
| D6  | **A heal never hides a regression.** The healed run is judged by the same checks; on fail the cache is not updated and heals are suspect                                                                           | Self-healing that rewrites the test until it passes is the main way AI testing tools lie.                                                                                                                                                                        | active                |
| D7  | **Vacuity rule:** a test with no hard check (only "no console errors" style guards) cannot pass                                                                                                                    | Otherwise an agent that clicks nothing passes every test on a healthy page.                                                                                                                                                                                      | active                |
| D8  | Orchestration: a hand-written typed state graph                                                                                                                                                                    | Small, no dependency.                                                                                                                                                                                                                                            | superseded by D9      |
| D9  | Orchestration: **LangGraph JS** (`crawl → plan → runTest ×N (Send) → writeReport`)                                                                                                                                 | Fan-out with `Send`, a graph that renders itself (`npm run graph`), and the vocabulary interviewers expect. Found and worked around its `maxConcurrency: 1` Send bug.                                                                                            | active                |
| D10 | **Lean crawler:** capped BFS, same-origin, skips logout/delete/external/asset links                                                                                                                                | The planner needs a site map, not an index. Destructive links must never be clicked by a crawler.                                                                                                                                                                | active                |
| D11 | **Ports and adapters** (`core/ports.js`): crawler, planner, executor, judge, reporter, store are interfaces                                                                                                        | Each day's work landed behind an interface, so the demo path kept working every evening.                                                                                                                                                                         | active                |
| D12 | **Zod schemas are the contract** for every persisted or JSON shape (suites, recordings, reports, config)                                                                                                           | One source of truth for validation, types (`z.infer` via JSDoc) and the UI.                                                                                                                                                                                      | active                |
| D13 | **Local web UI** (Fastify + SSE + React) on top of the same `startRun()` as the CLI                                                                                                                                | The first real runs showed a CLI hides what the agent is doing. Live view and review screens need a UI; no hosted backend or database.                                                                                                                           | active                |
| D14 | **Committed suites** (`--suite`, written in the UI or exported) with recorded steps; `--no-heal` in CI                                                                                                             | Users must be able to own and review their tests; CI must be deterministic and token-free.                                                                                                                                                                       | active                |
| D15 | **Quality, theme and visual checks are advisory by default** (`warn`), opt-in to `fail`                                                                                                                            | A tester that fails every build on day one for a contrast warning gets switched off.                                                                                                                                                                             | active                |
| D16 | **Theme conformance from the production build:** read CSS custom properties, audit every screen in every theme, by value not by name                                                                               | Works on any app with no config; comparing values lets `--theme-from` check one product against another that names its tokens differently.                                                                                                                       | active                |
| D17 | **Visual regression with pixelmatch against approved baselines**, not an LLM looking at screenshots                                                                                                                | Deterministic and free. The LLM is only asked questions the test author wrote (`visual` expectation).                                                                                                                                                            | active                |
| D18 | **Login once per run with plain Playwright**, credentials only from env, `storageState` restored per test                                                                                                          | The AI never sees the password; reports and suites never contain it; tests start logged in and the agent is told not to log out.                                                                                                                                 | active                |
| D19 | **App hints are optional** (`data-testid`, `data-aie2e-*`); everything works without them                                                                                                                          | Generality is the requirement. Hints make replay more stable and give developers control when they want it (masks, components, hover-revealed controls).                                                                                                         | active                |
| D20 | **Reusable GitHub Action** (composite, inputs passed as env vars)                                                                                                                                                  | One `uses:` line for any repo; env vars instead of `${{ }}` in the script prevent script injection.                                                                                                                                                              | active                |
| D21 | **Evaluation by seeded bugs** (buggy-shop, 12 known bugs) plus a real third-party app (TodoMVC) with injected regressions                                                                                          | "It found bugs" is not a claim without ground truth; detection rate and false positives are measured, not asserted.                                                                                                                                              | active                |
| D22 | **Third-party noise is declared, never silently filtered** (suite `ignore`, `AIE2E_IGNORE_*`)                                                                                                                      | Analytics, error reporters and font CDNs fail guards on real apps; a declared list keeps them visible in the evidence and in review.                                                                                                                             | active                |
| D23 | **On Linux the agent's Chrome runs without Chrome's sandbox**, like Playwright's own launches (`AIE2E_CHROME_SANDBOX` opts back in)                                                                                | CI runners and root containers cannot start a sandboxed Chrome; the first GitHub run errored on every test.                                                                                                                                                      | active                |
| D24 | **The agent gets a read-only `harnessStatus` tool and ends with a structured report**                                                                                                                              | It could not tell its own mistake from an app failure. Read-only and never used for the verdict, so asymmetric trust holds.                                                                                                                                      | active                |
| D25 | **The visual judge gets the page text as context, not tools**                                                                                                                                                      | One yes/no question needs grounding, not a loop: one call, predictable cost.                                                                                                                                                                                     | active                |
| D26 | **Model presets by role**; strong models where calls are few (planner, judge)                                                                                                                                      | The agent makes dozens of calls per test; the planner and judge a few. Stagehand 3.7.3 limits the agent's models.                                                                                                                                                | active                |
| D27 | **Plain-English insights are deterministic** (`reporter/insights.js`), shared by the UI, `report.html` and the run list                                                                                            | Every sentence must trace to a judge check; an LLM summary could contradict the verdict and costs tokens on 0-token replays.                                                                                                                                     | active                |
| D28 | **Checks carry an optional `label`** in plain words; reports show it, the judge ignores it                                                                                                                         | Non-developers read "The cart holds 1 product", not an XPath. Keeping it out of the judge keeps verdicts deterministic.                                                                                                                                          | active                |
| D29 | **Summary first, developer view one click away** (toggle remembered per browser; developer details inside each journey)                                                                                            | Two readers, one tool: a manager or tester reads the story; a developer still gets every tab unchanged.                                                                                                                                                          | active                |
| D30 | **The AI explains failures, after the verdict, and says when the test itself is wrong** (`judge/failureExplainer.js`)                                                                                              | Deterministic text can say _where_ it broke, not _why_. One call per failure, 0 on green runs; a category keeps false alarms honest. Never an input to the verdict.                                                                                              | active                |
| D31 | **Our own agent loop as an option** (`AIE2E_AGENT_ENGINE=loop`): AI SDK tools on Playwright's accessibility snapshot, acting by element ref                                                                        | Any model for the agent (Stagehand 3.7.3 cannot drive the 5.5 family; v4 removed `agent()`), our tools natively, no LLM to find an element. Default stays Stagehand until a side-by-side run says otherwise.                                                     | active (experimental) |
| D32 | **The showcase is the real UI over exported server answers**, static, read-only (`demo:export`, `--mode demo`)                                                                                                     | A link that cannot fail or leak a key during a call; exporting through the real routes means the showcase shows exactly what `npm run ui` shows.                                                                                                                 | active                |
| D33 | **Who did what, with what input:** every test result names the input of each part (AI agent, Playwright, judge), and suites are edited per part                                                                    | Interviewers and users asked where the AI ends. Showing the agent's exact instruction, the steps Playwright replayed and who wrote them, and the judge's checks makes the hand-offs checkable; users can write steps by hand.                                    | active                |
| D34 | **A deployed instance is locked down in code**, not only by the platform: access code, host allow-list, no targets on the server's network, the owner's login only on listed apps, small runs (`server/access.js`) | A public page that starts browsers with the owner's key is a spending risk, a way into the host's network (SSRF) and, with `.env` logins, a way to phish the password. Each guard is tested; the local UI is unchanged.                                          | active                |
| D35 | **Explore deeper by looping the graph over discovered screens** (`--rounds`): round 2 starts on the screens round 1's passing tests reached, replayed from their recordings                                        | The crawl only follows links, so screens behind a click are invisible to the planner and only get visual checks. A test that already went there is the cheapest, replayable way back. Judged from that screen, so it cannot pass on what was already shown.      | active (experimental) |
| D36 | **A new recording is kept only after it replays once on its own**, with no AI, judged on the test's own checks                                                                                                     | A passing agent run can rely on something its steps do not capture (a wait, a hover). Finding out on the next run, or in CI, is too late. One extra browser run per new recording; replays stay free.                                                            | active                |
| D37 | **Recorded steps prefer a test id, a real id, or the control's role and name over Stagehand's absolute XPath**, upgraded during the replay check when the agent's click already changed the page                   | Absolute XPaths break when one wrapper is added; a role and name ("the button named Generate") is what a person sees and survives layout changes. Generated ids (React `_r_e_`, Radix) change between renders and are never used. The XPath stays as a fallback. | active                |

## Alternatives not built

### Engine

| Alternative                                                            | Why not (now)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Stagehand v4**                                                       | Too new at the start of the project; breaking API changes were still landing. 3.x is stable and documented. Re-checked Fri 30 Oct (spike, 4.3.0): it launches and attaches fine (Playwright can still connect over CDP, the 5.5 model ids reach the API), but it now runs through a browser extension with an RPC runtime and `agent()` is gone, so moving means a new browser lifecycle _and_ our own loop. We built the loop first (D31) on Playwright's accessibility snapshot, which needs no Stagehand for acting at all; v4's `act`/`observe` can be added later as one more tool. |
| **Magnitude** as the engine                                            | Strong vision-first agent, but it owns the whole loop. We need our own judge and our own record/replay; it is credited as a reference for the planner/runner split.                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Playwright Test Agents** (planner/generator/healer)                  | They generate `.spec.ts` files for a human to maintain. We wanted JSON steps the tool itself replays and heals, plus an evidence judge. Credited as a reference.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Pure vision agent** (screenshots + coordinates)                      | Expensive per step and hard to replay deterministically. DOM-based actions record to selectors; vision is used only for the `visual` expectation.                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Browser pool** (reuse Chromium across tests)                         | Faster, but leaks state between tests. Isolation first: one fresh browser per test; pooling is an optimisation for later.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Crawl by clicking** (an agent explores every button before planning) | Expensive before any test exists, and clicking blind can submit, delete or pay. Passing tests already know safe paths to those screens (D35).                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **One graph per page, compiled together at the end**                   | Pages are not independent: a page behind a click needs the steps that reach it, and data made on one changes another. Rounds over discovered screens keep the path to each screen (D35).                                                                                                                                                                                                                                                                                                                                                                                                 |

### Judging

| Alternative                                      | Why not                                                                                                                                                               |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Trust the agent's "success"**                  | The main failure of naive AI testers: agents report success they did not achieve. Measured early on and designed out (D5).                                            |
| **LLM judges the final screenshot**              | Missed "did it _change_" questions from one image and was fooled by stale state. Kept only for author-written visual questions, with start, step and end screenshots. |
| **Screenshot diff as the pass/fail judge**       | Too noisy for functional checks (any copy change fails). Used for visual regression only, against approved baselines, with masks and live regions hidden.             |
| **Auto-heal that rewrites expectations**         | Would turn every regression into a green build. Heals may change _how_ a step is done, never _what_ is checked (D6).                                                  |
| **Hard-fail on quality/theme/visual by default** | Too many false alarms on day one; `warn` by default, `fail` when a team is ready (D15).                                                                               |

### Product

| Alternative                                     | Why not (roadmap)                                                                                                                  |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **TypeScript**                                  | JSDoc + `tsc --checkJs` gives the same checking without a build step; faster on a 5-day deadline (D3).                             |
| **Hosted backend + database, dashboard**        | Out of scope. Runs, suites and baselines are files: easy to commit, diff and review in a PR.                                       |
| **Tracing platform** (Langfuse / LangSmith)     | Useful once the core works; the report already shows every step, heal, token cost and screenshot. Roadmap.                         |
| **Multi-model support and comparison UI**       | One model string (`AIE2E_MODEL`) works with any provider the AI SDK supports; a comparison UI is roadmap.                          |
| **DTCG design-token files** as the theme source | Most apps do not ship one; reading the production CSS works everywhere. A token-file import is roadmap.                            |
| **AI triage of visual diffs**                   | Nice for review, but would put an LLM back into a deterministic check. Humans approve or reject in the UI for now.                 |
| **Run comparison** (this run vs last run)       | Baselines and the cache already carry history; a side-by-side view is roadmap.                                                     |
| **Playwright `.spec` export**                   | Suites already replay with no LLM and run in CI; exporting would create a second format that must stay true to the first. Roadmap. |
| **MCP server** (other AI tools call this one)   | Useful for agentic IDEs, but no requirement or demo step needs it. Roadmap.                                                        |
